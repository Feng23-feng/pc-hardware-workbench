# 使用方式

## 在 Codex 中调用

```text
$pc-hardware-workbench
```

可以直接描述目标，不必先判断应该走哪条流程：

- “帮我看看当前电脑的硬件配置。”
- “游戏里偶尔卡顿，先帮我判断还缺哪些证据。”
- “这份 HWiNFO CSV 里有没有异常趋势？”
- “我想给这张显卡降温，先确认能不能安全调参。”
- “现在这套配置值得升级显卡还是继续保留？”

## 常见输入

Skill 可以处理对话描述、硬件报告、CSV、传感器快照、事件日志引用、截图说明和
手动填写的基线。图片只作为有限证据；CSV 和时间序列仍是趋势判断的基础。

如果信息不足，Skill 会给出最小补证动作，而不是直接猜测参数。

## 调参请求

调参请求至少需要：

- 电脑形态与主要硬件；
- 当前稳定状态；
- 当前控制值；
- 固定测试场景；
- 恢复路径和中止条件。

信息不足时不会生成可直接套用的数字。条件齐全后，也只提供一个单变量、可回退的
测试计划，由用户手动应用。

## 调试记录与恢复

当排查会跨多轮、使用多份证据、包含一次参数变更，或需要防止聊天上下文丢失时，
Skill 会在私有本地目录维护一个案卷。案卷记录当前目标、证据 ID、基线、实验、
通过/中止条件、恢复方式和下一步，但不会逐轮保存整段聊天。

开始新对话时可以直接说“从上次的 case 恢复”。紧凑 `Resume` 摘要会给出现场状态，
同时要求重新确认当前设置和证据新鲜度。原始 CSV、截图或日志只有在用户同意后才复制
进案卷。

## 排障请求

请描述最接近的现象、发生时间和最近的软硬件变化。存在焦味、液体、破损、鼓包或
异常高温时，Skill 会优先停止性能测试并提示处理物理安全问题。

## 遥测分析

优先提供原始 CSV 或结构化 `SensorSnapshot`。单张监控截图可以描述某个瞬间，但
不能代替时间窗口、采样间隔和缺失值记录。

## 隐私

硬件报告只读、默认省略序列号，并在脱敏模式下遮蔽可识别的设备字段。公开报告前
仍应人工检查。详见 [隐私与安全边界](privacy-and-safety.md)。
