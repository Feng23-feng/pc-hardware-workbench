# 文件星系迭代复盘与防回归清单

本文件记录 2026-11-02 至 2026-11-04 文件星系改版中出现过的真实问题。目的不是追溯责任，而是防止同类错误再次进入页面、生成器或发布流程。

## 不再重犯

### 1. 数据更新不等于渲染器重写

当视觉语言已经被接受，而需求只是更新文件数量、权重、标签或关联关系时，必须复用现有渲染器，只替换数据适配层。

只有出现旧架构无法满足的具体需求时，才允许重写。重写前必须同时保留旧版截图和旧版渲染入口，作为视觉回归基线。

此前的错误结果包括：

- 同心轨道退化成原子模型；
- 球体与轨道不属于同一采样函数；
- 标签重叠；
- 前后遮挡顺序错误；
- 已经调好的相机和轨道关系被整体丢弃。

### 2. 视觉验收不能由功能测试代替

文件数量、链接、JavaScript 语法和控制台无报错，不能证明页面“看起来正确”。

每次影响场景的改动都要检查：

- 默认视角；
- 正负极值俯仰；
- 至少四个水平环绕角度；
- 拉近和拉远；
- 展开分区前后的轨道；
- 默认标签、悬停、选中和关联标签；
- `1440px` 桌面、`960px` 中间宽度和 `390px` 手机宽度。

### 3. 不得用加速掩盖掉帧

轨道运动的流畅度必须通过真实时间步长、缓存投影路径和复用像素缓冲解决。

禁止通过提高全局公转倍率，让偶发掉帧显得“看起来更快”。公转速度应服务于层级、质量和可读性，而不是动画性能测试。

### 4. 标签默认要可发现

文件小球的名字和分区元数据必须默认可见，但保持较低的视觉权重。悬停、聚焦、选中时再提亮。

选中文件后，关联球体、关联路径和关联名字必须同步高亮。不能让用户只看到连线，却还要逐个悬停寻找关联名字。

选中期间，未被选中且未关联的名字应进一步降低亮度和透明度来减少拥挤，但仍须保持可辨认；取消选择后恢复默认层级。

选中状态必须有显式的“重置选择”入口。该入口只清除选择、关联高亮、连线和降噪状态，不应顺带重置相机或退出当前分区。

窄屏可以缩小字体和最大宽度，但不能把“能否理解页面”完全依赖悬停。

### 5. 冻结页面必须可复现

生成器必须统一处理换行符再计算正文、字节数和哈希。Windows 工作区中的 `CRLF` 与干净检出中的 `LF` 不能产生两个不同的“同一版本”。

所有排序必须显式固定大小写和区域规则。`zh-CN` 与 `en-US` 不能改变分区、文件或 JSON 属性顺序。

生成 ZIP 和冻结哈希时应使用规范化文本。不要把 Git 工作区原始换行格式直接当成版本内容。

### 6. JSON 文本流不能依赖宿主机格式

PowerShell 的 JSON 输出可能随运行环境和对象类型产生格式差异。生成文件应使用压缩输出，或进行语义比较；不能只依赖本地生成成功。

关键验证必须至少在以下环境中通过：

- `zh-CN`；
- `en-US`；
- 干净 Git 检出；
- 与 GitHub Actions 相同的 Windows PowerShell 5.1。

### 7. “指纹”必须解释来源

页面上的摘要只表示 86 个 Git 跟踪文件的路径、规范化内容哈希和字节数汇总。它不是设备指纹，不读取硬件、浏览器或用户身份。

面向用户的文案统一使用“文件集摘要”，并说明用途是确认页面与清单对应。

### 8. 大标题不使用正文标点

主标题、章节标题和高亮大字不使用逗号、句号、冒号或分号制造语气。需要停顿或分行时，用短句、空格或受控换行解决。

一句完整的话才保留句末标点。不要为了“看起来像文案”给视觉标题加多余标点。

### 9. 多列表单必须固定顶部基线

同一行里的下拉框和输入框必须从顶部对齐。辅助说明可以在控件下方独立占据高度，但不能把没有说明的相邻控件向下撑开。

网格容器使用 `align-items: start`，字段容器使用 `align-content: start` 和 `align-self: start`。视觉验收必须覆盖三列、两列和一列布局，不能只看单个控件。

## 发布完成条件

只有以下条件全部满足，才能说“已冻结并推送”：

1. 生成器 `-Check` 通过。
2. 站点检查、版本一致性和尾随空格检查通过。
3. 同一输出在 `zh-CN` 和 `en-US` 下通过。
4. 远端提交 tree SHA 与本地提交 tree SHA 一致。
5. 同一远端提交的 Windows CI 成功。
6. 同一远端提交的 Pages 构建成功。
7. 线上 `FROZEN.json` 的版本、日期、文件数、聚合摘要、页面摘要和字节数正确。
8. 线上页面实际显示了本次用户可见改动。

任何一项失败都不能用“页面能打开”代替完成。
